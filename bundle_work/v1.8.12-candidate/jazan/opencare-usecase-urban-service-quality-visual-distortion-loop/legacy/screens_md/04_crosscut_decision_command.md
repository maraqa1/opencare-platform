# Screen 04 — Cross-cutting decision command queue

**Path**: `/jazan-performance/use-cases/urban-service-quality-visual-distortion-loop/decisions`
**Implements**: Cross-cutting function view (accessible from any level via persistent sidebar)
**Renders for**: Performance Office reviewer doing their daily decision triage

This is the highest-leverage demo screen — it's where the customer should hear themselves say "yes, that's how we want to work."

## Purpose

Aggregate every open decision candidate across all KPIs and all 25 municipalities in one queue. Let the reviewer triage the queue by risk score, drill into a specific case via a detail drawer (without leaving the queue), and take action (Approve / Request revision / Escalate / Create ticket / Notify owner) — all in one screen.

## Regions

### Region 4.1 — Page header

- Title (bilingual): `Decision command centre · مركز قيادة القرار`
- Subtitle: `Awaiting review · N candidates · M high-risk` (counts computed live)
- Mode chip: `Demo data · seeded`
- Locale toggle

### Region 4.2 — Status counters strip

Six-column strip showing counts by decision status across the whole queue:
- New decisions
- Under review
- Approved
- Escalated
- Tickets created
- Emails sent

Each counter is clickable — clicking filters the queue table below to that status.

### Region 4.3 — Decision candidate queue (table)

One row per open decision candidate. Columns:

- Decision ID (font-mono, e.g. `JZN-DEC-1007`)
- Municipality (bilingual)
- KPI name (short form)
- Risk score (numeric, threshold-coloured)
- Forecast breach probability (%)
- Top recommendation (intervention type, short form)
- Owner (assigned role/team)
- Status pill
- Due date
- Actions column (icons: view detail, approve, escalate, ticket, email, etc.)

Default sort: risk score descending; ties broken by oldest-first.

A row click opens the detail drawer (Region 4.4) without leaving the page.

### Region 4.4 — Selected decision detail drawer

Appears below or beside the queue when a row is selected. Shows the full case detail without navigating away. Contents:

- **Header**: case ID, municipality (bilingual), KPI, generated timestamp, "Awaiting Performance Office review" pill
- **Case detail panel** (3-column strip):
  - Left column: Municipality, KPI, Current value
  - Middle column: **Rationale** — bilingual prose explaining the situation
  - Right column: **Recommended actions (ranked)** — top 3 from `output.jazan_recommended_intervention`, condensed
- **Numeric strip**: target, forecast breach probability, anomaly z-score, risk score
- **Take action row**: five action buttons (Approve / Request revision / Escalate / Create ticket / Email owner)
- **Audit footnote**: "Every action is human-authorised, audit-logged, and bilingual. Platform never escalates externally without approval."
- **"Open full case workspace"** link → navigates to Level 3 case workspace for this case

The detail drawer is functionally equivalent to Tab 3.3 (Decision command tab inside the case workspace), but rendered inline below the queue so the reviewer can triage multiple cases quickly without losing the list.

## Data bindings

| Component | Source | Binding type |
|---|---|---|
| Status counters | `decision.jazan_decision_action_events` grouped by current_status | Query |
| Decision queue | `decision.jazan_generated_service_decisions` joined with `dim_jazan_municipality`, `contracts/kpi.yaml`, `output.jazan_recommended_intervention` (top 1) | Query |
| Detail drawer — case detail | Same row from `jazan_generated_service_decisions` plus stored evidence snapshot | Query (stored snapshot) |
| Detail drawer — recommendations | `output.jazan_recommended_intervention` top 3 for this (muni, kpi) | Query |
| Detail drawer — bilingual rationale | Stored on candidate row, generated by `RT-JAZAN-DECISION-CANDIDATE` | Query (stored) |
| Action button POSTs | `backend/routes.yaml` — five endpoints | Backend |

## Interactions

| Trigger | Behaviour |
|---|---|
| Counter click | Filter queue by that status |
| Row click | Open detail drawer; URL appends `?selected={decision_id}` for bookmarking |
| Action button (drawer) | Confirmation modal → POST to backend → audit log entry → row state updates |
| "Open full case workspace" | Navigate to Level 3 case workspace |
| Sidebar nav back to Level 1 | Navigate to strategic landing |

## Bilingual

The bilingual rationale is the most visible Arabic content on this screen. Both languages are rendered side-by-side (or stacked on narrow viewports). The rationale text is editable — the reviewer can refine the auto-draft before approval.

## Renderer requirements

- Sortable, filterable data table with row-click drawer pattern
- Status-coloured numeric chips and pills
- Bilingual editable text panel
- Five-button action row with confirmation modal pattern
- Live counter updates when status changes
