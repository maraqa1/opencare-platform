# Source Data and Metadata

## Required Raw Tables

| Table | Purpose |
| --- | --- |
| `raw.rcm_claims` | Claim lifecycle, billed value, expected value, submitted status, and paid value. |
| `raw.rcm_financial_postings` | ERP or general-ledger postings used as the cash truth anchor. |
| `raw.rcm_referrals` | Referral or acquisition source used to connect revenue to channels. |

## `raw.rcm_claims`

Required fields:

- `claim_id`
- `encounter_id`
- `patient_id`
- `payer_id`
- `department_id`
- `claim_date`
- `submission_date`
- `payment_date`
- `claim_status`
- `gross_billed_amount`
- `contracted_amount`
- `paid_amount`
- `overpayment_flag`
- `source_system`
- `updated_at`

Accepted statuses:

- `open`
- `submitted`
- `paid`
- `denied`
- `appealed`
- `writeoff`
- `closed`

## `raw.rcm_financial_postings`

Required fields:

- `posting_id`
- `claim_id`
- `encounter_id`
- `gl_account`
- `posting_date`
- `posting_type`
- `posting_amount`
- `source_system`

The posting table anchors cash collection and reconciliation. If a target platform has a different finance ledger, map it to this logical shape before mart construction.

## `raw.rcm_referrals`

Required fields:

- `referral_id`
- `encounter_id`
- `acquisition_channel`
- `referral_source`
- `referral_date`

## Sensitivity

- Claim and posting data is financial and commercially sensitive.
- Patient identifiers must not be surfaced in dashboards unless the receiving platform has explicit access controls.
- Payer contract performance is commercially sensitive and should be restricted to approved finance and payer-relations roles.
